## Sobre

Serviço completo de encurtamento de URLs, construído de ponta a ponta: API em
**FastAPI**, persistência no **Supabase** (PostgreSQL), interface em **HTML, CSS e
JavaScript puros** e **deploy automatizado** por GitHub Actions.

O mesmo servidor entrega o site e a API — um único endereço, sem CORS em produção.

## Funcionalidades

- **Encurtamento** — códigos de 7 caracteres gerados com `secrets` (aleatoriedade criptográfica, não `random`)
- **Redirecionamento** — `GET /{codigo}` leva à URL original
- **Contagem de cliques** — cada acesso incrementa o contador no banco
- **Tratamento de colisão** — se o código sorteado já existe, sorteia outro automaticamente
- **Validação de URL** — via Pydantic (`HttpUrl`), rejeitando entradas inválidas com 422
- **Copiar para a área de transferência** — um clique, com retorno visual
- **Estados de carregamento e erro** — mensagens específicas para cada falha possível
- **Interface responsiva e acessível** — HTML semântico, foco visível, `aria-live` nos avisos

## Stack

| Camada | Tecnologia | Por quê |
|---|---|---|
| **API** | FastAPI + Uvicorn | Validação automática via type hints e documentação OpenAPI de graça |
| **Banco** | Supabase (PostgreSQL) | Postgres gerenciado, sem servidor para administrar |
| **Frontend** | HTML + CSS + JS (ES Modules) | Sem framework e sem build: o objetivo era dominar a base |
| **Testes** | pytest | 7 testes, todos isolados do banco real |
| **CI/CD** | GitHub Actions | Testes a cada push; deploy só se eles passarem |
| **Hospedagem** | Render | Deploy contínuo via webhook |

## Como funciona

```
  ┌──────────────┐
  │   NAVEGADOR  │
  └──────┬───────┘
         │  1. POST /encurtar   { "url_original": "https://site-bem-longo.com/..." }
         ▼
  ┌─────────────────────────────────┐
  │   FASTAPI  (Render)             │
  │                                 │     2. INSERT  { codigo, url_original }
  │   • valida a URL (Pydantic)     │ ──────────────────────────────►┌────────────┐
  │   • sorteia um código (secrets) │                                │  SUPABASE  │
  │   • monta a URL curta (BASE_URL)│ ◄──────────────────────────────│ PostgreSQL │
  └─────────────────────────────────┘     3. ok                      └────────────┘
         │
         │  4. { "url_curta": "https://encurtaa.onrender.com/aB3xY9k" }
         ▼
  ┌──────────────┐
  │   NAVEGADOR  │  mostra o link + botão copiar
  └──────────────┘


  Depois, quando alguém abre o link curto:

  GET /aB3xY9k  ──►  FastAPI  ──►  SELECT url_original WHERE codigo='aB3xY9k'
                                   UPDATE qtd_cliques = qtd_cliques + 1
                        │
                        └──►  HTTP 307 Redirect  ──►  site original
```

## Rodando localmente

Pré-requisitos: **Python 3.12+** e uma conta gratuita no [Supabase](https://supabase.com).

### 1. Clone o repositório

```bash
git clone https://github.com/thainaoliv/EncurtaA-.git
cd EncurtaA-
```

### 2. Crie o ambiente virtual

Um ambiente virtual (*venv*) isola as bibliotecas deste projeto das do resto do
computador — assim uma versão instalada aqui não quebra outro projeto.

```bash
python -m venv .venv

# Windows (PowerShell)
.venv\Scripts\Activate.ps1

# Linux / macOS
source .venv/bin/activate
```

### 3. Instale as dependências

```bash
pip install -r backend/requirements.txt
```

### 4. Prepare o banco

No painel do Supabase, crie a tabela `links` (**SQL Editor → New query**):

```sql
create table links (
  id           bigint generated by default as identity primary key,
  codigo       text   not null unique,
  url_original text   not null,
  qtd_cliques  int    not null default 0,
  criado_em    timestamptz default now()
);
```

> O `unique` em `codigo` não é decoração: é ele que garante que dois links nunca
> compartilhem o mesmo código. O backend conta com esse erro do banco para
> detectar colisões.

### 5. Configure as variáveis de ambiente

Crie o arquivo `backend/.env`:

```env
SUPABASE_URL=https://seu-projeto.supabase.co
SUPABASE_KEY=sua-chave-anon
BASE_URL=http://127.0.0.1:8000
ALLOWED_ORIGINS=http://localhost:5500,http://127.0.0.1:5500
```

Pegue `SUPABASE_URL` e `SUPABASE_KEY` em **Settings → API** no painel do Supabase.

> ⚠️ `SUPABASE_URL` é o endereço do **banco** (`...supabase.co`) — não o endereço
> onde a aplicação está hospedada. Trocar os dois faz o backend mandar as consultas
> para si mesmo e responder 500.

O arquivo `.env` está no `.gitignore`: **credenciais nunca vão para o repositório.**

### 6. Suba o servidor

```bash
cd backend
uvicorn api:app --reload
```

Pronto:

| Endereço | O que é |
|---|---|
| http://127.0.0.1:8000 | o site |
| http://127.0.0.1:8000/docs | documentação interativa da API (Swagger) |

## Testes

```bash
cd backend
python -m pytest -v
```

```
7 passed
```

Os testes cobrem a geração de código (1.000 iterações verificando tamanho e
alfabeto), a busca com link existente e inexistente, a contagem de cliques, o
caminho feliz da criação, o **tratamento de colisão** e a **propagação de erro
real**.

Nenhum deles toca o banco de verdade: cada um injeta um dublê do cliente Supabase
via `monkeypatch`. Os testes rodam offline, em menos de 1 segundo, e nunca sujam
dados reais.

## API

| Método | Rota | Descrição | Resposta |
|---|---|---|---|
| `GET` | `/` | Página inicial | HTML |
| `POST` | `/encurtar` | Cria um link curto | `{ "url_curta": "..." }` |
| `GET` | `/{codigo}` | Redireciona para a URL original | `307` ou `404` |
| `GET` | `/docs` | Documentação OpenAPI | HTML |

```bash
curl -X POST https://encurtaa.onrender.com/encurtar \
  -H "Content-Type: application/json" \
  -d '{"url_original": "https://github.com"}'

# {"url_curta":"https://encurtaa.onrender.com/aB3xY9k"}
```

## Esteira de deploy

Definida em [`.github/workflows/ci.yml`](.github/workflows/ci.yml):

```
git push
   │
   ├─► instala o Python e as dependências
   ├─► roda os 7 testes  ──── falhou? ──► para aqui, sem deploy
   │                                      (produção fica intacta)
   └─► passou? ──► dispara o deploy hook do Render ──► site atualizado
```

O ponto central: **o deploy só acontece se os testes passarem.** Código quebrado
não chega ao ar.

## Decisões de arquitetura

Algumas escolhas deste projeto foram deliberadas. Vale explicar o raciocínio:

<details>
<summary><strong>Quem monta a URL curta é o backend, não o frontend</strong></summary>

<br>

`criar_link()` devolve **apenas o código** (`aB3xY9k`); quem monta a URL completa é
o `api.py`, lendo a variável `BASE_URL`.

Seria mais fácil o frontend concatenar `location.origin + "/" + codigo`. Mas aí o
endereço público passaria a ser definido em dois lugares — e dois lugares
divergem. A regra adotada: **um só dono por informação.** O backend sabe em que
endereço está rodando, então é ele quem responde isso.

Efeito colateral útil: a API serve qualquer cliente (app, CLI, outro serviço), não
só este site.

</details>

<details>
<summary><strong>Colisão de código é tratada, não ignorada</strong></summary>

<br>

Com 62 caracteres possíveis em 7 posições existem ~3,5 trilhões de combinações —
colisão é improvável, mas improvável não é impossível.

Em vez de checar antes ("esse código já existe?"), o código tenta inserir e trata o
erro do banco:

```python
except Exception as erro:
    if "duplicate key" in str(erro):
        continue        # sorteia outro e tenta de novo
    else:
        raise           # erro de verdade: não engolir
```

Checar antes criaria uma *condição de corrida*: entre a checagem e a inserção,
outra requisição pode gravar o mesmo código. A restrição `unique` do banco é a
única verificação realmente atômica. E o `else: raise` é essencial — um `except`
que engole tudo transforma falha de conexão em bug silencioso.

</details>

<details>
<summary><strong>Os testes usam dublê em vez do banco real</strong></summary>

<br>

Cada teste substitui o cliente Supabase por uma classe falsa via `monkeypatch`.
Mais trabalhoso de escrever, mas:

- rodam **offline**, em menos de 1 segundo
- não poluem o banco com lixo de teste
- testam o **meu** código, não a disponibilidade do Supabase
- o teste de colisão fica possível — forçar uma colisão real é inviável, mas um
  dublê lança `duplicate key` na primeira chamada e funciona na segunda

</details>

<details>
<summary><strong>O mesmo servidor entrega o site e a API</strong></summary>

<br>

O FastAPI serve o `index.html` na raiz e monta as pastas `css/`, `js/` e `assets/`.
Site e API na mesma origem significam **zero problema de CORS em produção** e um
único serviço para hospedar.

A ordem das rotas no arquivo é intencional: `GET /{codigo}` vem **por último**,
porque é um curinga que casa com qualquer caminho de um segmento. Declarada antes,
roubaria as requisições das rotas específicas.

</details>

<details>
<summary><strong>Os arquivos CSS são numerados</strong></summary>

<br>

```
01-reset.css  →  02-tokens.css  →  03-base.css  →  04-layout.css  →  05-components.css
```

CSS é cascata: em caso de empate na especificidade, **o que vem depois vence**. O
número no nome deixa essa dependência explícita no sistema de arquivos, em vez de
escondida na ordem das tags `<link>`. Do mais genérico (reset) ao mais específico
(componentes).

</details>

<details>
<summary><strong>Nenhum framework no frontend</strong></summary>

<br>

React resolveria isso em menos linhas. Mas o objetivo deste projeto era entender a
base: manipulação de DOM, `fetch`, `async/await`, ES Modules, eventos de formulário
e cascata de CSS — sem camada de abstração escondendo o funcionamento.

O código é organizado em módulos com responsabilidade única: `api.js` (comunicação),
`clipboard.js` (copiar), `main.js` (orquestração e DOM).

</details>
